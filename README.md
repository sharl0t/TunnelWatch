# TunnelWatch — Network Tunnel & Process Monitor

GUI-утилита на Python (PyQt6) для мониторинга сетевых соединений процессов в реальном времени. Показывает активные соединения и определяет, идут ли они **напрямую**, через **VPN-туннель** или через **локальный прокси**.

## Возможности

- Сканирование сетевых соединений каждые 2 секунды.
- Классификация соединений по типу маршрутизации:
  - `НАПРЯМУЮ` — трафик идёт через основной шлюз (зелёный);
  - `VPN / ТУННЕЛЬ` — приложение направлено в туннель (красный);
  - `VPN / ВНУТР. ПРОКСИ` — соединение с локальным SOCKS5/HTTP-прокси (красный);
  - `VPN / ЯДРО` — соединения процессов-ядер (оранжевый).
- Группировка соединений по процессу в одну строку.
- Скрытие служебных демонов (`xray`, `happd`, `sing-box`).
- Текстовый фильтр по имени процесса или IP-адресу.
- Панель статистики: всего сокетов, через VPN/прокси, напрямую, ядро/демоны.
- Тёмная тема оформления с цветными бейджами статуса.

## Скриншот интерфейса

| Колонка | Описание |
|---|---|
| Процесс | Имя процесса (или имя с количеством соединений в режиме группировки) |
| PID | Идентификатор процесса |
| Удаленные адреса / Сокеты | Протокол, IP и порт удалённой стороны |
| Локальный интерфейс | Сетевой интерфейс маршрута (`eth0`, `tun0`, `lo` и т.д.) |
| Маршрут / Обработка | Текстовое пояснение, как обрабатывается трафик |
| Тип | Цветной бейдж типа соединения |

## Требования

- **ОС:** Linux (используется команда `ip route get`).
- **Python:** 3.9+.
- **Права:** root для доступа к соединениям всех процессов (через `sudo`).
- **Python-зависимости:**
  - `PyQt6`
  - `psutil`

## Установка

Создание виртуального окружения и установка зависимостей:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install PyQt6 psutil
```

## Запуск

Требуются права root, иначе список соединений будет пустым:

```bash
sudo .venv/bin/python tunnel_monitor.py
```

Либо с активированным окружением:

```bash
source .venv/bin/activate
sudo "$(which python)" tunnel_monitor.py
```

## Использование

- **Группировать по процессам (1 строка)** — объединяет все соединения одного процесса в одну строку, суммируя PID, адреса и интерфейсы. Если хотя бы одно соединение процесса идёт через туннель/прокси, вся строка помечается красным.
- **Скрыть xray / happd** — исключает из таблицы служебные процессы-ядра.
- **Фильтр по процессу или IP** — мгновенная фильтрация строк при вводе.
- **Двойной клик по строке** — открывает отдельное немодальное окно со **всеми** сокетами выбранного процесса (или всех PID, объединённых в строке в режиме группировки). В этом окне намеренно НЕ применяются фильтры основного окна: показываются все TCP-статусы (включая `LISTEN`, `TIME_WAIT`, `CLOSE`, `CLOSE_WAIT`), UDP, loopback-соединения и сокеты без удалённого адреса. Окно автоматически обновляется каждые 2 секунды (без новой зависимости — `QTimer`), наследует тёмную тему и показывает бейдж типа соединения в колонке «Тип». Для соединений без удалённого адреса выводится прочерк «—».

## Как определяется тип соединения

1. Соединения считываются через `psutil.net_connections(kind="inet")`.
2. TCP-соединения фильтруются по статусам: `ESTABLISHED`, `SYN_SENT`, `SYN_RECV`, `CLOSE_WAIT`; соединения без удалённого адреса пропускаются.
3. Обычный loopback-трафик отбрасывается, но соединения к локальным прокси-портам остаются.
4. Маршрут определяется командой `ip route get <IP>` (результат кешируется). Для loopback интерфейс — `lo`.
5. Тип классифицируется по приоритету:
   - процесс входит в список демонов → `VPN / ЯДРО`;
   - соединение к локальному прокси-порту → `VPN / ВНУТР. ПРОКСИ`;
   - интерфейс содержит ключевые слова туннеля и приложение в списке проксируемых → `VPN / ТУННЕЛЬ`;
   - интерфейс туннеля, но приложение не проксируется → `НАПРЯМУЮ` (direct bypass);
   - иначе → `НАПРЯМУЮ`.

### Настраиваемые списки (в `tunnel_monitor.py`)

| Переменная | Назначение |
|---|---|
| `proxied_apps` | Приложения, трафик которых направляется через туннель (`electron`, `shelly-ui`, `spotify`, `discord`) |
| `tunnel_daemons` | Служебные процессы-ядра (`happd`, `xray`, `sing-box`) |
| `common_proxy_ports` | Типичные порты локальных SOCKS5/HTTP-прокси |
| `tunnel_keywords` | Ключевые слова в имени интерфейса, указывающие на туннель |

### Основные компоненты кода

- `BadgeDelegate` — делегат отрисовки цветных бейджей в колонке «Тип».
- `NetworkTunnelMonitor` — главное окно и вся логика мониторинга.
  - `refresh_connections()` — сбор, фильтрация и классификация соединений.
  - `get_route_interface()` — определение интерфейса маршрута с кешированием.
  - `resolve_proc_info()` — получение имени и пути процесса по PID.
  - `_update_stats()` — обновление карточек статистики.

## Ограничения

- Утилита рассчитана на Linux: жёстко использует `ip route get` и ключевые слова интерфейсов.
- Без прав root доступ к соединениям других процессов ограничен.
- Список прокси-портов и проксируемых приложений задан статически и требует ручной правки под конкретную конфигурацию.
